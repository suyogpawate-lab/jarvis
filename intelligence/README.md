# JARVIS local screen perception

JARVIS keeps its existing Android screen-cast receiver and Accessibility controller.
For an explicit screen request, the latest in-memory frame is classified locally by
MobileCLIP-S0. Only the resulting short label/score list and the fresh Accessibility
hierarchy are sent to Groq. The JPEG is not uploaded to Groq or written to disk.
Groq remains the reasoning/planning model; MobileCLIP-S0 is not a captioner,
OCR engine, object detector, or action planner.

## Model files

Place these files under `models/vision/`:

- `mobileclip_s0_image.onnx`: image encoder exported from the MobileCLIP-S0 checkpoint.
- `mobileclip_s0_prototypes.json`: text embeddings generated by the matching MobileCLIP-S0
  text encoder. Image and text encoders must come from the exact same checkpoint.

Set `JARVIS_VISION_ONNX` and `JARVIS_VISION_PROTOTYPES` to override those paths.
The JSON manifest schema is:

```json
{
  "schema_version": 1,
  "input_size": [256, 256],
  "mean": [0.48145466, 0.4578275, 0.40821073],
  "std": [0.26862954, 0.26130258, 0.27577711],
  "labels": [
    {"label": "Android home screen with app icons", "embedding": [0.1, 0.2]}
  ]
}
```

The two-dimensional embedding above is illustrative only; the real vectors must
match the exported encoder's output dimension. The preprocessing metadata must
match the export's processor exactly. Do not use arbitrary CLIP/SigLIP vectors.

## Termux runtime

Install the optional runtime dependencies with Termux packages where available:
`pkg install python-numpy python-pillow python-onnxruntime`.
The model is loaded lazily on the first explicit screen request and retained in
the process for reuse. It does not load at JARVIS startup. Missing model files or
runtime dependencies are reported as unavailable; the existing Accessibility
hierarchy and Groq text reasoning continue to work.

## Privacy and control boundaries

Frames and Accessibility snapshots remain ephemeral. MobileCLIP produces global
image embeddings and candidate scene labels only; it does not localize controls.
Natural-language control therefore targets exact Accessibility element indexes.
If no unambiguous accessible target exists, JARVIS must ask for clarification rather
than invent coordinates. Consequential actions remain blocked by the existing guard.
